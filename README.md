# 그물지우개

AI가 만든 영상(업스케일 과정)에 생기는 **그물무늬(대각선 격자 무늬)만 골라서 지우고**, 다시 압축할 때 생기는 손실 없이 저장하는 웹 도구입니다.
영상은 **브라우저 밖으로 나가지 않습니다.** 디코딩, 보정, 인코딩이 모두 이 탭 안의 WebAssembly(ffmpeg.wasm)와 Web Worker에서 이루어집니다.

## 원리

- 그물무늬는 노이즈가 아니라 AI 업샘플러가 남기는 "롤러 자국"이라서 **항상 같은 각도(45°), 같은 간격(2~3px)** 으로 나타납니다.
- 영상의 밝기(Y) 채널을 128×128 타일(50% 겹침, sqrt-Hann 창)로 나눠 FFT로 주파수 지도를 만들고, **네 모서리의 대각선 고주파 영역만** 부드럽게 감쇠한 뒤 역FFT로 다시 합칩니다(WOLA).
- 온갖 방향과 간격이 섞인 진짜 디테일(나뭇잎, 지푸라기)은 거의 건드리지 않습니다. 보통 픽셀당 평균 2~3/255 단계만 바뀝니다.
- 색(UV) 채널과 오디오는 원본을 그대로 둡니다.

## 저장 형식

| 형식 | 설명 |
| --- | --- |
| 무손실 MP4 (기본) | H.264 lossless(qp 0). 보정한 픽셀 외에는 원본 디코딩 결과와 비트 단위로 같습니다. 파일이 크고, QuickTime이나 iOS에서는 재생되지 않을 수 있습니다(VLC, Premiere, DaVinci에서는 열림). |
| 무손실 MKV | FFV1. 10bit 영상까지 비트 단위로 보존합니다. |
| 초고화질 MP4 | H.264 CRF 12. 어디서나 재생됩니다. |

- 구간 지정(예: `0-2, 6-9`)을 하면 그 구간만 보정하고, 나머지 프레임은 원본 픽셀을 그대로 둡니다. 경계는 0.2초에 걸쳐 부드럽게 전환됩니다.
- 오디오와 메타데이터는 스트림 복사(`-c copy`)합니다. 컨테이너가 원본 오디오 코덱을 담을 수 없을 때만 변환합니다.

## 개인정보와 보안

- 페이지에 `Content-Security-Policy: connect-src 'self'`를 걸어서 외부 서버로는 어떤 데이터도 보낼 수 없습니다.
- ffmpeg 엔진(wasm)까지 모두 같은 도메인에서 서빙하므로 서드파티 CDN 요청이 없습니다.
- 입력 파일은 WORKERFS로 **마운트만** 하고, 메모리로 복사하거나 전송하지 않습니다.

## 로컬 실행

```bash
npm install
npm run dev   # http://localhost:5173
```

`npm run build`는 `node_modules`의 ffmpeg.wasm 파일을 `public/vendor/`로 복사합니다. 이 폴더는 git에 올리지 않습니다.

## Vercel 배포

`vercel.json`에 빌드 명령(`npm run build`), 출력 폴더(`public`), 보안 헤더(COOP/COEP/CSP)가 들어 있어서 저장소를 연결하면 그대로 배포됩니다.

## 처리 구조

```
파일 ──(WORKERFS 마운트)──▶ ffprobe(일회용 인스턴스): 스트림 정보 + 키프레임 위치
                           │
          키프레임+1 경계로 구간 분할 (seek 낭비 최소화, 프레임 단위 정확)
                           │
 디코더 레인 ×2 ──raw YUV──▶ 필터 워커 풀(Y 평면 FFT) ──▶ 인코더 레인 ×2 ──▶ 세그먼트(.nut)
                           │
            concat(구간 길이 명시) + 원본 오디오 copy ──▶ 결과 파일 다운로드
```

- ffmpeg.wasm의 멀티스레드 코어는 exec 사이에 간헐적으로 멈추는 문제가 있어서, 단일 스레드 인스턴스 여러 개를 레인으로 나눠 병렬 처리합니다.
- ffmpeg.wasm의 `ffprobe`는 실행 후 인스턴스를 Abort 상태로 만들기 때문에, 일회용 인스턴스에서만 실행합니다.
